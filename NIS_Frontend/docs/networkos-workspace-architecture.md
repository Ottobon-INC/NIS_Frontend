# NetworkOS Workspace Architecture

## 1. Core Principle
The frontend is organized around **Contextual Workspaces**, replacing isolated pages.

## 2. Identified Workspaces

### Founder Intelligence Cockpit (Dashboard)
- **Primary Purpose:** "WHAT NEEDS MY ATTENTION?"
- **Information Architecture:** Action + Context. Prioritizes:
  - Decisions requiring founder action (Founder Decision Queue)
  - Validations requiring founder review
  - Network matches requiring approval
  - Introduction drafts requiring review
  - Important relationship signals
  - Active opportunities
  - Meaningful recent outcomes

### Contact Intelligence Workspace (Contact 360)
- **Primary Purpose:** Central relationship intelligence command center.
- **Unifies:** Person Intelligence, Company Intelligence, Signals, Evidence, "How They Help Us", "How We Help Them", Relationship Engine, Current Context, Meetings, and Opportunities.

### Meeting Intelligence Workspace
- **Primary Purpose:** Transforms conversational context into extracted needs.
- **Embedded Workflows:** Brief → Capture → AI Extraction → Founder Validation.

### Trusted Context Workspace
- **Primary Purpose:** Manages the versioned, auditable, founder-approved intelligence.
- **Embedded Workflows:** Validation, Versioning, Auditing, and Correction.

### Opportunity Workspace
- **Primary Purpose:** Independent workspace retaining all origin context (Person, Company, Meeting, Trusted Context). 
- **Embedded Workflows:** Solution Matching, Match Ranking, "Why This Match?", Introductions, Conversations, and Outcomes.

### Capability Intelligence Workspace (Products & Services)
- **Primary Purpose:** Knowledge layer mapping internal capabilities to Solution Matching.

### Network Intelligence Workspace
- **Primary Purpose:** "Who in our network can help solve this problem, and why?" Explaining match relevance.
